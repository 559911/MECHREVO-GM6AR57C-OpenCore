# 本地补丁逐条说明（v14 / WhateverXe 0.8.0）

适用：**macOS 15.8.2（24H232）· AppleIntelTGLGraphics 16.0.0 · MECHREVO GM6AR57C（0x4688 / Hybrid MUX）**。
所有结论均逐条对照上游 0.8.0 源码原文核对，未使用第三方教程。

## 一、EFI 内 WhateverXe 的两处补丁（必须保留）

产物：`EFI/OC/Kexts/WhateverXe.kext/Contents/MacOS/WhateverXe`
SHA-256：`5dbfbbbff483babcfd5ede660e1140ecc38c1e45af1b8901358d48e7925eb053`（1,835,768 字节级）

### P1 · ADL-S 内屏背光去掉 FUSE bit24 门禁

- **本机问题**：`FUSE(0x42000) = 0x8C000000`，bit24 = 0。
  上游 `adlsCapturePanelPWM()` 与 `wrapADLSPanelBacklight()` 原生都要求
  `wells!=~0U && fuse!=~0U && (wells&1) && (fuse&0x01000000)`，门禁永远不成立 →
  PWM 抓不到、亮度写不进 → 内屏只有 0 / 满亮两档。
- **补丁**：两处都去掉 `fuse & 0x01000000` 要求，只保留「显示电源井已上电 `(wells&1)`」作为访问条件；
  并在 `wrapADLSPanelBacklight()` 里把亮度夹到 16 位（`brightness > 65535 ? 65535 : brightness`）。
- **上游 0.8.0 状态**：两处门禁原样保留（源码约 13832 / 13861 行），未修。
- **运行时判据**：`ADLSPanelPWMReady = Yes`；亮度是中间档（实测 `24182/65403 = 37%`）。
- ⚠️ **升级注意**：0.8.0 在 `kern_xe.cpp:13782` 新增了**第三处**同样的 bit24 门禁，
  属于「从 BIOS 捕获面板时序」（`tglPanelTimingBIOS`），只服务 Display13 面板路径；
  本机 `adlnOutputWiring.panel = false`，那段是死代码，**故意不改**。
  **不要全局替换 `(fuse&0x01000000)`**，会把改动面扩大到无关路径。

### P2 · 唤醒黑屏 · 面板供电 no-op

- **本机问题**：熄屏时原生调 `AppleIntelFramebufferController::hwSetPanelPower(0)`，
  真的切断 eDP 面板与 AUX 供电；唤醒后必须重新训练 eDP 链路，而这块第三方面板重训确定性失败
  （`LinkUpdate: 1.0 event: TrainingError`、`DBUF 2 power up timeout`、`Phase 1 of link training failed`），
  结果是「管道在跑、链路没通」→ 全黑，只有冷启动能恢复。
- **补丁**：hook 原生 `hwSetPanelPower`，`wrapPlainPanelPower` 只放行上电 `state=2`，
  其余状态返回成功且**不动硬件**，把重训整条绕开。
  锚点要求 `panelFn == address+0x48652` 且入口 18 字节机器码逐字节吻合，校验不过就不 hook。
- **上游 0.8.0 状态**：`hwSetPanelPower` 仍只用于 donor 属性补丁与 `processDisplay13Panel`（本机不启用），
  没有 hook 电源状态；README 把系统睡眠唤醒列为 experimental 且只在 MIPI DSI 机型验证过。
- **运行时判据**：`WhateverXePanelPowerHooked = Yes`；唤醒后 `WhateverXePanelPowerCall` 回 `02`。

## 二、第 3 处补丁已删除（不要恢复）

原 P3 是「Doze 期间不武装 DC6/DC9」的本地钩子（13 版及以前）。v14 起改用苹果帧缓冲驱动自带参数：

```
-nodisplaysleepDC6
```

- `AppleIntelFramebufferController::start` 在 `0x3f615` 解析该参数，命中就把 `+0xC29` 置 0（默认 1）；
- `setDCState` 在 `0x47336` / `0x4746B` 两处检查 `0xC29`，为 0 就跳过
  `enableHWDC6()` / `enableSWDC6()` 的装载；
- `0xC29` 全文件只在 `start` 写、只在 `setDCState` 读，靶点精确。
- 比补丁更轻：补丁让整个 `setDCState(true)` 返回，参数只关 DC6/DC9 装载，原生其余流程照跑。
- **该参数是苹果驱动内部参数，WEX 文档没有背书，靠实测确认**：
  2026-11-08 本次开机累计 8 轮熄屏唤醒，正式判据 2 轮连续熄屏 193 / 223 秒，
  零 `TrainingError`、唤醒后状态 4、面板供电回 `02`、零新增 panic。

**判据变化**：v14 的 IORegistry 中 `TGLWEXDozeDCGuardReady` / `TGLWEXFBStateRouted`
**应当不存在**。这两条属性出现，说明装成了旧三补丁版，属于倒退。

## 三、已作废、不要再打的补丁

| 补丁 | 作废原因 |
|---|---|
| `recoveryRequested` 的 Sequoia 白名单 | 0.8.0 把 OS 判断整个删掉，改为 `checkKernelArgument("-disablegfxfirmware")` 后按 donor 逐字节校验放行，覆盖面比本地补丁更宽 |
| Sequoia MMIO 校验 | 上游已处理 |
| `impostor.dylib` 的 `24H32` build 门禁 | 0.4.1 的 impostor 不含 `24H32` 字面量、带 `@loader_path/descriptor.dylib`，与 0.4.0 一致，上游保持已修状态 |

## 四、系统侧两个用户态补丁（不在 EFI 内）

由 `脚本/1-装完Graphics包后补丁.command` 完成，**每装 / 升级一次 Graphics pkg 都要重跑**。

| 补丁 | 位置 | 内容 | 不做的后果 |
|---|---|---|---|
| MTL 命令缓冲泄漏 | `AppleIntelTGLGraphicsMTLDriver`，`0x7ed87` | `75 0d`（jne，跳过释放）→ `90 90`，随后整包 `codesign -f -s - --deep` | `-[MTLIGAccelCommandBuffer init…]` 每次提交分配 76 KB 却不释放，Chromium 32 GB 池约 30 分钟吃满，GPU 进程 SIGTRAP |
| VADriver 禁用 | `/Library/GPUBundles/AppleIntelTGLGraphicsVADriver.bundle` | 改名为 `.bundle.disabled` | AppleGVA 跨 GPU 像素转换崩溃，真实播放闪退 |

- 版本指纹：`0x7e9cb = bf10200100e839fe0100`（0.3.2 / 0.4.0 / 0.4.1 三版一致），
  脚本校验不匹配就拒绝修改；0.4.1 **仍未修**。
- 0.4.1 的 `Sequoia.pkg` 会把 VADriver 装成启用状态，且带 `<relocate/>`：
  安装前若卷上还留着旧 `.disabled`，载荷会被写进它里面。脚本先把旧 `.disabled` 移去备份再改名。
- 硬解统一走独显 NVDEC：H.264 1080p ≈168 fps、HEVC 4K ≈118–132 fps，零崩溃。
  `VTIsHardwareDecodeSupported()` / `UsingHW` 会误报，判据只看出帧数。

## 五、升级时的裁决规则

1. 上游发布 WEX > 0.8.0 或 Graphics > 0.4.1 时，**逐条比对源码**再决定补丁去留，不能沿用本版结论。
2. 升级 Graphics 包前先做二进制同异比对（`pkgutil --expand-full` + `cmp`）：
   三个图形主文件与已装版本逐字节相同 → donor 偏移不漂，不必重验；
   若 `AppleIntelTGLGraphics` / `Framebuffer` / `MTLDriver` 有变化 → 所有补丁重新验证。
3. 两补丁绑死 macOS 15.8.2 / 24H232 / `AppleIntelTGLGraphics 16.0.0` 的 donor 偏移
   （`+0x4CA1E` / `+0x43576` / `+0x3906C` / `+0x48652`）；系统升级后任一校验不过就整体不装。
4. **判断 hook 是否生效必须看运行时 IORegistry**，不能只看源码里有函数。
   `Requested=Yes / Ready=No` → donor 校验没过，立即回退。
