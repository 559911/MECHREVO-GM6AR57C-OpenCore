# 本机编译说明（MECHREVO GM6AR57C）

本目录是上游 **SMCNvidiaGPU v1.8.5** 的源码原样副本（MIT，见 `LICENSE`）。
`README.md` / `README.en.md` 里提到的 **RTX 5080（GB203）、macOS 26.7.1** 是上游作者的验证环境，
**不是本机配置**；本机的实际情况是：

| 项 | 本机 |
|---|---|
| 显卡 | NVIDIA RTX 4070 Laptop（`10de:2820`，8 GB，Ada） |
| 驱动 | NullMoth NVRM **2.7.2** |
| 系统 | macOS **15.8.2（24H232）** |
| 插件 | 按 v1.8.5 源码**原样编译**，未加任何本机补丁 |
| 产物 | `驱动/SMCNvidiaGPU.kext`（`CFBundleVersion = 1.8.5`，二进制 `794e8d06…`，126,000 B） |

## 为什么必须在这台机器上编译（或重编）

`kext/build.sh` 在编译前会运行 `kext/nvrm_bindings.py`，从本机
`/Library/Extensions/NVRM.kext/Contents/MacOS/NVRM` 现场提取驱动入口偏移、机器码签名与
`OBJGPU` 字段偏移，生成 `kext/nvrm_bindings.h`。因此：

- **换 NVRM 版本 = 必须重编**，否则定位不到驱动，风扇、功耗、温度等传感器全部为空；
  上游 v1.8 发布说明原文：「1.7 及更早的 kext 在 2.7.2 上定位不到驱动，风扇、功耗等传感器会全部为空；升级驱动时请一并升级 kext。」
- 本机 2.7.2 的绑定基线：driver sha `4aeb8a5e…`、anchor `nv_xnu_phys_for_kernel_va @ 0x16030`。
- 发布包里**没有**预生成 `nvrm_bindings.h` / `nvrm_bindings_legacy.h`，也没有 `out/` 编译产物，
  避免把本机绑定表当成通用文件；它们会在构建时现场生成。

## 编译

需要 VirtualSMC 与 Lilu 源码提供插件 SDK 头文件（本目录不含），用环境变量指向：

```bash
cd 驱动/源码/SMCNvidiaGPU-1.8.5
VSMCDIR=/path/to/VirtualSMC-master \
LILUDIR=/path/to/Lilu-master/Lilu \
  bash kext/build.sh ./build-out
```

未设置这两个变量时，脚本会在仓库上级目录找 `vsmc/VirtualSMC-master` 与
`vsmc/Lilu-master/Lilu`。构建还需 `xcrun` 的 Kernel.framework 头文件；`MODE=debug`
会生成逐次轮询日志的调试版，日常用默认的 `MODE=release`。

编译出的 `build-out/SMCNvidiaGPU.kext` 用 `rsync -a` 替换 `EFI/OC/Kexts/SMCNvidiaGPU.kext`，重启后核对：

```bash
sysctl kern.nvgpudiscover   # 应含 used=anchor
sysctl kern.nvgpustate      # 应为 polling mask 0xff / 500 ms（这是绑定成功终态）
sysctl kern.nvgputemp       # 非 0
sysctl kern.nvgpupower      # 单位 mW，约 20500
```

## 已知副作用

上游 1.8.5 无条件注册 `F2Ac` / `F3Ac` 两个风扇键。本机 GPU 没有独立风扇（风扇由 EC 直控），
这两条会一直显示 0 转，属显示噪音，不是故障。`F0Ac` / `F1Ac` 在本机根本不存在。
